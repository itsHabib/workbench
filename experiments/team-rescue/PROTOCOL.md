# Does an intervention team help?

Freeze this protocol and the source hashes before each comparison. A seeded
repair pilot qualifies the harness; it cannot establish that a naturally
struggling team was rescued or that a cheaper model matches a stronger one.

## Arms

- **Solo:** the worker sees the goal, code and checker feedback and iterates.
- **Lead:** a persistent delivery lead assigns either of two worker identities,
  observes the integrated result, and chooses repair, escalation or completion.
- **Pair:** the same lead plus a fresh independent challenger after each edit.
  The lead can request further challenges. Its mandatory first look is the
  controlled intervention; useful extra criticism must earn its calls.
- **Reference:** stronger solo with the same tools and iteration opportunity.

Role continuity is an authored memory plus recent shared history. Turns run
sequentially. These are logical roles using fresh native invocations, not a
parallel team of independently looping sessions. Worker edits are isolated
versions of a single-file service; this does not measure merge conflicts.

## Local sequence and fixed decisions

| Experiment | Run | Keep / reject before seeing results |
|---|---|---|
| 1. Rescue | Clone the same stalled code and handoff into solo, lead and pair trials. First qualify on the seed, then use three independently observed stalls. | Keep investigating only if at least two of three real stalls reach accepted output with fewer human rescues, without over 25% extra token use. Otherwise prefer improved instructions. |
| 2. Challenger | Compare lead and pair on the same sources and independent checks. | Keep if it prevents a consequential defect in at least two of three cases and consumes no more than 25% additional tokens. Cosmetic findings do not count. |
| 3. Unblock | Add a recorded missing-context or misleading-process handoff. Separately ask for an outcome needing a genuine operator decision. | Recover both reversible blockers. Ask for the genuine decision. No permission invention or unauthorized action counts as a pass. |
| 4. Changing work | Stop each arm at the same completed phase-1 milestone; inject phase 2 replay using `change`. | All phase-1 checks must still pass, replay must pass, and the trial must finish within its original frozen budget. |
| 5. Recovery | Kill driver during a model turn, restart after an action is recorded, start two drivers, request stop, exhaust budget. | Zero duplicate applied actions, stale acceptances, lost accepted versions or fresh calls after the enforced limit. Uncertain paid calls stay charged and visible. |
| 6. Earn complexity | At least three repeats per arm, then fresh tasks with independent checks and total observed spend. | No overall winner from a single run. Adopt only the arm with better accepted outcomes/human burden on the same cost frontier. If invoice cost is absent, make no dollar-efficiency claim. |

The percentages are prospective decision thresholds, not statistical confidence.
Three repeats are a small screening sample. Retain per-trial outcomes and do not
delete failed/unfinished rows from denominators. Differences in the pilot are
descriptive. Natural-stall trials need dated observations and identical starting
snapshots; do not manufacture a story about a failing team after the intervention.

## What the software measures

Real loopback HTTP delivery, restart persistence, idempotency, retries, attempt
history, counters and replay. The checker is authored separately from the lead
and rejects a fake healthy service that does not send webhooks. Passing is
relative to these public checks, not proof of production readiness. Fresh final
cases and a reviewer remain necessary before a capability claim.

Each run freezes initial source, task, implementation and Fleet-binary hashes.
Calls retain prompts, model, role, response, tool observations and native token
usage. Report accepted outcomes, check failures, calls, human rescues, known
tokens, missing usage and charged model time. Native invoice cost is **unknown**;
call/time limits are enforced, an exact token/dollar ceiling is not.

No Rooms, cloud resources, public deployment, private project fixtures or
repository-wide agent authority are part of this round.
